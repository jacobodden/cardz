Cardz docs

Architecture

A local-first scorekeeper: a static React app that keeps every session in the browser's IndexedDB. No server, no sync, no sign-in.

AGENTS.md at the repo root is the short working reference (conventions, schema, where things live). This page is the longer overview.

Stack

UI
Vite, React 19, React Router, Tailwind CSS v4 (@theme tokens, no config file)
Storage
Dexie.js over IndexedDB; components read with useLiveQuery
Offline
PWA via vite-plugin-pwa, auto-updating service worker that precaches the build
Hosting
GitHub Pages under the /cardz/ base path
Tests
Vitest + fake-indexeddb (unit), Playwright (e2e and visual)
Lint
oxlint

The router uses basename={import.meta.env.BASE_URL}. GitHub Pages has no SPA fallback, so public/404.html stores the requested path in sessionStorage and redirects to /cardz/, where the app restores it.

Data model

One Dexie database, cardz, with five tables:

games     ++id, &slug, name, description, min_players, max_players, config_schema
sessions  ++id, game_id, title, status, config_json, created_at
players   ++id, session_id, name, order_index
rounds    ++id, session_id, round_number, data_json
scores    ++id, round_id, player_id, score, data_json

A session belongs to a game and has players and rounds; each round has one score per player. data_json holds game-specific values, such as a round's trump or a player's bid. Game definitions live in code, and seed.ts upserts them into games on every load so updates reach installed copies.

Games

Each game is a pure module implementing CardGame (src/games/types.ts) and registered by slug in src/games/index.ts. The main hooks:

  • getRounds(playerCount, config): the round plan. Fixed games (Up and Down, Pay Me) generate every round up front; open games (High and Low Score) add rounds as they are played.
  • getRoundSchema(round): the inputs to collect per player or per round.
  • computeScore(meta, inputs): turn inputs into scores.
  • Optional validateRound (e.g. the hook rule), getRoundInfo (chips like trump or wilds) and getDefaultConfig.

To add a game: write the module, register it, add unit tests in tests/unit/ and a rules page in docs/games/.

Themes

Light/dark mode and the color theme are independent. Mode is the .dark class on <html>, stored in localStorage('theme'). The color theme is data-palette on <html>, stored in localStorage('palette'), with each theme's tokens in src/index.css and its entry in src/themes.ts. A startup script in index.html applies both before first paint, using the registry that vite.config.ts injects. Layout.tsx keeps <meta name="theme-color"> in step with the felt color.

The header is always felt and pinned to the top. Installed on iOS, the app draws under a transparent status bar (black-translucent, viewport-fit=cover) and the header pads by env(safe-area-inset-top), so the status bar shows the theme's felt with no seam. Page gutters use the safe-x utility to clear the notch in landscape.

Winner celebration

When a game ends on screen (Finish, or the last Up & Down round), SessionPage pops a burst from the winner's trophy. The particles are pure functions in src/celebration/particles.ts (unit tested), drawn on a full-screen canvas by components/Celebration.tsx. A theme's celebration field picks the burst: confetti by default, seeds for Bagel, footballs for Skol. Opening a game that already finished does not pop; tapping the trophy pops again. The automatic pop is skipped under prefers-reduced-motion, which the visual tests turn on so snapshots stay still.

PWA and icons

The manifest and service worker are configured in vite.config.ts. After the auto-updating service worker installs a new build and reloads, UpdateToast shows "Cardz updated" once, with a link to What's new, when src/changelog.ts has a newer top entry than the one saved in localStorage('lastSeenUpdate'). Fresh installs see no toast, and builds with no new entry update quietly. Install icons are generated from public/pwa-icon.png with npm run generate-pwa-assets. The header logo is a separate transparent image, public/app-logo.png.

Deployment

.github/workflows/deploy.yml builds on every push to main and publishes dist/ to GitHub Pages (Settings → Pages → Source: GitHub Actions).
